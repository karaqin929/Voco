## 模块一：打卡三条链路

### 链路 A：导入日报打卡 ✅（v116 日期选择器全部按设计落地）
- 调用链：showImportDialog → onImportInput(350ms 防抖) → validateImportInput（JSON 顶层 4 键 + summary 9 键；Markdown parseSmartReport）→ renderImportPreview → importReport → importJsonDailyReport / importDailyReport → 四表写入 → updateProgress/topics（仅当日）→ loadHome → renderStreakCard。
- v116 核查：日期选择器重置/`_importDateTouched`/`detectReportDate` 三正则/两路径 `date === getLocalToday()` 护栏/`errors_fixed` 单调护栏 —— 全部真实存在且接线正确。
- 审计发现并修复（v117）：
  - **F1【高危·跨账号污染】** updateProgress 两处 count 查询无 `.eq('user_id', uid)` —— 拆分后库里并存两个账号数据，下次导入会把对方行数计进 words_learned/errors_fixed，且单调护栏把污染值永久锁死。→ 已加过滤。
  - **F2【高·双计】** 「同日已有日报」无查重 —— upsert 静默覆盖 + progress/topics 双计。→ importReport 新增同日查重，命中即 toast 拒绝。
  - **F3【中】** 弹窗会话内换贴第二篇时日期残留上一篇自动识别值。→ 识别不到时回落今天。
  - **F4【中】** 裸日期兜底会命中 JSON 内容值里的日期（想法/例句）→ 今日日报被静默填成过去日期。→ JSON 意图只认 "date" 键，裸日期兜底仅 Markdown 启用。
  - **F5【中】** 日期选择器无 max，可导未来日期（熊条永远看不到的行）。→ max=今天。
  - **F6【中低】** 成功后 1 秒窗口可二次提交。→ `_importing` 互斥锁。

### 链路 B：句型复习打卡 ✅（v115 写回六项全部在位）

  - **F7【高·曲线重置】** reviewPatternItem 的 sm2 在锚点卡命中库行重绑**之前**计算 —— 历史视图复习会把该句真实曲线重置为全新卡（interval 回到 1）。→ sm2 移到 p 定案之后。

### 链路 C：到期复习打卡 ✅（一处写回口径升级）
- 任务 3 数字 = totalDueVocabCount + dueErrorCards()；done = deckTotal===0 时 deckReviewed>0，否则当日 voco-vocab-done 戳；两戳均为「今日完成过」语义（非「今日无剩余」），任务 3 戳可掩盖同日新增到期词 —— 记录为已知取舍。
- 审计发现并修复（v117）：
  - **F9【中·重复行永久到期】** reviewErrorItem limit(1) 只推进同文本重复错题的第一行，其余行永不前移 → 次日永久到期。→ 对齐词汇口径改为全行推进（非主行且未到期不动）。

### 设计取舍（记录不修）
- 完成戳与写回成功脱钩（v115 明确选择：不吞用户完成事实）。
- due 复习从不写 correct_in_review（v99 设计：由 SQL 清理脚本负责，「纠正20次」成就依赖它）。
- 任务 2 的 15 句截断 vs「打卡完成」语义落差（逐日消化，文案未体现剩余量）。
- 入库非事务（任一表失败半途遗留，重试时文本查重自愈；progress 双计已由 F2 堵住）。
- words_learned 非单调（v116 实际行数口径，与 errors_fixed 单调护栏哲学不一致但可接受）。

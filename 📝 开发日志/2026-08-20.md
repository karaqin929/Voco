## 🔑 核心机制 1：SM-2 队列断层修复（用户漏洞分析 → 修正方案）

**用户诊断（部分正确）**：运行时 `.concat(expressionDeck(parsed))` 拼凑队列 = 「假入库」——临时工阅后即焚，记忆曲线断裂。**修正诊断**：JSON 路径导入时已 INSERT（不存在蒸发），真 bug 四处：

1. **双行双曲线**：复习时对非库行盲 INSERT，与导入行同文并存 → 两张卡、两条曲线、两个 next_review_date
2. **队列无文内去重**：同日重复出现的句子未去重
3. **Markdown 路径蒸发（真）**：sentence_patterns 从未入库 → 此处「阅后即焚」为真，已补 INSERT
4. **积压无界**：旧「今日优先」排序把历史欠账永远压底

**修复四件套**：
- **纯库捞**：`getDueSentencesQueue(_speakAll)`——loadSpeak 每次进页拉 patterns 表 → stampPatternTags → dedupePatternsByText → newCards（needsReview===true 且无 next_review_date，date_added desc）先行 + dueCards（next_review_date asc），上限 15
- **文本锚定 UPSERT**：reviewPatternItem 库行直接 UPDATE；非库行先按 targetSentence/better 文本命中库行改 UPDATE，未命中才 INSERT（与 v100 句型锚定反查同思路）
- **文本去重**：dedupePatternsByText（v103 单词去重先例）——有曲线行优先、created_at desc，保一行
- **同构补全**：importDailyReport Markdown 路径补 sentence_patterns INSERT（source_topic '核心句型'），JSON/Markdown 双桶同构

## 🔑 核心机制 2：日报一致性审计（全量钩稽）

**动机**：用户要求「全量 + 抽样」双重验收，杜绝历史遗留数据隐患。

**方法**：`runReportAudit()` —— reports limit 1000 全量拉取 → 换缓存清解析缓存 → 逐份：面板数 = getDayCounts(parsed)；列表实测数 = 临时换 `_ctxDate` 后调 getFilteredVocab('today') / allGrammarErrors() / parsedReportFor(date) 的 patterns / sentence_patterns → 四维逐一 ✓/✗。**今日行无条件重建 _reportParsed**（同源强制——修掉了「首页旧解析 vs 审计新拉取」分叉导致假 ✗ 的向量）。

**静态核验结论**：四维按构造恒等（同一数据桶/同一函数双侧调用），预期 100% ✓；若 ✗ 只可能是 parseFail（原始 JSON 损坏）——真问题。

## 🔑 核心机制 3：三视图句型复习页（URL 即状态）

`/shadowing?view=expressions|core&date=YYYY-MM-DD`——表达/核心两视图纯静态对比列表（renderExpressionList/renderCoreList，零 SRS 交互），历史提升区跳转落地处；default 视图 = 今日任务 2 打卡（翻卡 + SM-2）。`_ctxDate` 按日隔离：非今日且无日报 → 空态（0 条），绝不回退全局错题本或今日数据。

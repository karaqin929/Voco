# 开发日志 2026-10-20 — v132 熊屏挂死紧急修复（用户报「打开要很久很久，一直小熊」）

## 症状与取证（先查真相，再动手）

用户报：打开 Voco 要很久很久，一直显示「Voco小熊正一路小跑赶来」。取证链：

1. **边缘缓存实锤失效**：同一 URL 连打两次 `cf-cache-status` 均为 **DYNAMIC**——Render 免费层的 Cloudflare 前端**不缓存任何东西**，连 `immutable 1 年` 的 app.js 也不缓存。v129 的假设「写了 Cache-Control = 边缘会缓存」被实测推翻：头都正确，但平台不执行边缘缓存。
2. **源站慢**：暖机状态下 sw.js 首字节 **5.6s**；免费实例睡眠冷启动 30-60s+（v129 实测 32s）。且今天 v131 刚部署，全部客户端的 SW 缓存失效重建 = 每个资源都要穿透到慢源站。
3. **jsdelivr 实测失联**：本会话下载 chart.js 时 `cdn.jsdelivr.net` 返回 **000 连接失败**（换 unpkg 成功）——jsdelivr 在大陆网络不稳定是真实存在的风险，而 index.html 的 supabase-js 正是从 jsdelivr 加载的。
4. **熊屏有一条真实挂死路径**：`checkAuth` 裸 `await sb.auth.getSession()`——supabase-js 在令牌过期时会内部触发网络刷新、**无超时保护**；网络挂起 = checkAuth 永不返回 = 熊永不消失。且 `sb.auth.onAuthStateChange` 顶层裸调用，supabase-js 没加载成功时直接抛异常（`sb` 未定义），同样熊屏永远停留。

结论：不是「慢」一件事，是「慢 + 挂」两条链叠加：今天部署后所有缓存一次性失效撞上慢源站 = 很久很久；一旦某次网络挂起 = 一直。挂死路径在旧版本就存在，v131 没碰这条链——但今天把它逼出来了。

## 修复三层（v132）

### ① 熊屏防挂死（app.js，核心）
- 新增 `_safeGetSession()`：**8 秒超时竞赛 + try/catch 异常兜底 + `typeof sb === 'undefined'` 库缺失守卫**——超时/失败/库没加载，一律按未登录处理（显示登录屏），**加载屏绝不再无限停留**（失败路径留 console.warn 证据）。
- `checkAuth` 改走 `_safeGetSession`，对返回形状做全链守卫（`r && r.data && r.data.session`）。
- `loadConfig` 从 `await` 改为**不阻塞启动**：其 user_config 查询挂起时不再拖死首页渲染（同族防挂死）。
- `sb.auth.onAuthStateChange` 订阅加完整守卫链，库缺失时跳过订阅而不是裸抛。

### ② CDN 依赖自托管（index.html + server.py + sw.js）
- **supabase-js 2.118.0 / lucide 0.400.0 / chart.js 4.5.1** 三个 UMD 下载进 `🖥️ 前端/`，index.html 改本地引用——**jsdelivr 依赖清零**（supabase-js 加载失败 = 熊屏永挂的根因之一，自托管后此风险归零；三个文件进 SW 缓存清单，二次打开零网络）。
- 全部脚本加 **defer**：五个脚本从串行阻塞下载变并行下载（首次打开省掉 4 段源站往返的串行等待）。
- server.py 新增三条静态路由，IMMUTABLE 分层与其余 ?v=NN 资源一致。
- Tailwind CDN 保留（Cloudflare CDN，可达性稳定；换掉成本大、收益低）。

### ③ 版本三连 v132
- ?v=131→132（index 7 处：style + 3 库 + 3 应用脚本）、voco-v141→142、version.json + APP_VERSION v131→132、SW 注册 ?v=132；熊图独立查询串 ?v=129 不动。

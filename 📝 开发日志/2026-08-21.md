## 🔑 核心机制 2：熊条「打开停最左」真根因与硬化

**用户报告**：一进去显示 8.10-8.16（最左），要求「打开永远居右到今天 8.21；选历史日不回弹；手动滑动后保持位置」。

**真根因**：滚动盒 `overflow-x-auto` 来自 Tailwind CDN（异步生效）——首帧 CSS 未就绪时，`strip.scrollLeft = strip.scrollWidth` 在非滚动盒上被**静默丢弃**，锚定失效 → 停在最左。叠加旧 SW 缓存锁（voco-v113，502 风波遗留）使修复长期无法到达用户浏览器。

**硬化三件套**（v106）：
1. `overflow-x:auto` 改**内联样式**——滚动盒恒成立，不依赖任何 CDN 时序；
2. 首次渲染 = 同步兜底 + rAF 布局落定后按溢出量精确落锚 + `clientWidth>0` 可测量判定才落锚（隐藏态首渲自动顺延重试，绝不死锁左端）；
3. `_streakAnchored` 一次落锚后，一切重渲染（历史切换/后台补水/切页返回/手动滑动）只恢复 `_streakScrollCache` 绝不重锚定。

**SW 锁收尾**：用户按「无痕窗口验证 → Unregister + Clear site data + 硬刷新」执行后，Console 日志 `app.js?v=107` 确认新代码运行——502 风波遗留问题正式关闭。

## 🔑 核心机制 3：熊条最左对齐（v108，负外边距补偿法）

**用户报告**：横滑列表滑到最左边界时，第一个小熊往里缩进过多，未与上方「📅 打卡日历」图标左缘对齐。

**根因**：v98 为防「选中熊 scale-110 + 光圈被 overflow-x-auto 横向裁剪」给容器加了 `pl-1`（4px 左内距）——防裁切有效，但代价是 4px 视觉左缩。

**修复（补偿而非移除）**：容器追加 `-ml-1`（margin-left:-4px）：
- 盒子数学：容器左缘 = 图标左缘 − 4px（负外边距）→ 内容区起点 = +4px（pl-1 保留）→ **首熊卡左缘 === 图标左缘，严格同一条垂直参考线**；
- `pl-1` 原位保留：scale-110 + 光圈裁切缓冲不丢；scrollport 随负外边距左扩 4px，最左选中熊的光圈完整可见；
- 滚动锚定/恢复逻辑（`_streakAnchored`/`_streakScrollCache`）零改动——scrollWidth/scrollLeft 语义不受 margin 影响。

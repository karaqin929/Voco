## 🔑 核心机制 1：两个版本号（故意设计，不是误操作）

| 版本号 | 作用层 | 为什么需要 |
|--------|--------|-----------|
| `?v=NN`（v54） | HTTP / Cloudflare 缓存 | 资源 URL 换参数即可让 CDN 视为新文件 |
| `voco-vNN`（voco-v64） | Service Worker CacheStorage | 根文档 `/` 无法带 `?v=`，只有换缓存名才能替换 |

两者历史漂移差 10（v50 ↔ voco-v60），无碍。**每次部署必须各自 +1。**

## 🔑 核心机制 2：无损数据迁移与清洗层

```
Supabase 里的旧格式原文（永远不动）
        │ 读取
        ▼
parseSmartReport() ──┬─ JSON 分支：normalizeDailyData(原始JSON) ① → normalizeJsonReport → normalizeDailyData ②
                     ├─ Markdown 分支：parseReport → normalizeDailyData ③
                     └─ 导入入口：importJsonDailyReport 先清洗再入库
        ▼
UI 渲染（沉浸式播放器 / 复习页）
```

- 字符串句型 → `{id:'migrated_N', targetSentence, replacedSentence:'', explanation:'历史导入内容', isTodayCore:true}`
- 字符串错题 / 元组 `[wrong, correct, explanation]` / 残缺对象 → `{id:'mistake_N', type:'grammar', wrongSentence, correctSentence, explanation}`
- 桥接：mistakes 的 wrongSentence/correctSentence ↔ 内部 original/improved 契约（归一化层与纠错卡读取）
- 验收：18/18 通过（8.10 老格式 4 错题 + 3 句型全部存活零丢失；幂等一致）
- 铁律遵守：`parser.js` 一行未改，清洗层全部挂在 app.js 侧

## 🔑 核心机制 3：计数铁律（单一数据源，绝不分叉）

| 指标 | 布尔优先 | 兜底 |
|------|----------|------|
| 今日新词 `countTodayWords` | `isNewToday === true` | `date_added` 日期匹配（兼容完整时间戳） |
| 错词 `countMistakeWords` | `isMistake` | errors 表交叉比对 |
| 待复习 `countReviewWords` | `needsReview === true` | SM-2 `isDueBySrs`（next_review_date ≤ 今天） |

首页 todo / SM-2 卡片 / 单词页 `?tab=review` 三处共用同一函数，永不许硬编码。

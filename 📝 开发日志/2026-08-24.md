## 🔑 核心机制 1：50→24 复活的完整取证链（v115③）

**用户报告**：完成今日到期复习 50 张，返回首页显示「还剩 24 张」，且**全是词卡**（今天未导入日报 → 无今日生词 → 24 张全部是历史词）。

**取证三连**（用户在 Supabase 跑 SQL 实锤）：
1. 复活 24 行的 `last_reviewed_at` 大多是 **8.16 或 NULL**——若写回落库，此字段必为当天（8.24）→ **写回从未到达数据库**；
2. 排除「写错日期」（根本没写）与「重复行复活」（24 行里只有 existential/pivot 两词有双行，解释不了 24 张）；
3. 排除 SM-2 日期算术？——**并不**：审查发现 sm2 存在隐性分支 `Math.round(ivl*ef)`，历史脏数据（reps≥2 且 interval=0）会算出 **ivl=0 → next_review_date=今天 → 无限复活**。虽然本次实锤是「没写」而非「写错」，该分支仍是一颗地雷，一并钳制。

**根因**：fire-and-forget 写回（`handleReviewFeedback(...).catch(()=>{})`）+ 50 路并发 select+update + `update()` error 从不检查 + catch 空块全吞 → 写丢的卡本地态已变异（needsReview=false）会话内看似完成，刷新后按 DB 日期重算复活。**教训：写回可靠性是 SM-2 曲线存活的必要条件——「显示完成」≠「曲线落库」；静默吞错 = 现场零证据，修复必须留痕。**

**七件套**：① `enqueueVocabWrite` 串行队列；② `updateRowWithRetry`（error 检查 + 500ms 退避重试 + console.warn）；③ `resolveVocabRows`（主键直击 + ilike 文本兜底 + **同词全部到期行一并推进**）；④ find 未命中 → 卡组 ref 直接写回；⑤ sm2 全分支钳制最短 1 天；⑥ 错题/句型写回同构加固（句型 INSERT 入队不重试防双行）；⑦ `voco-vocab-done` 本地完成戳 + 首页任务 3 兜底。`markMastered` 同口径。

## 🔑 核心机制 2：双行考古（existential / pivot）

- **pivot**：两行 date_added 不同 → v103 查重上线前的**跨天盲插**（两天日报都列了它）；
- **existential**：两行 date_added 相同、一行带曲线一行素行 → 旧版**「复习 INSERT 行」遗留**（早期复习反馈新插一行照抄 date_added，曲线只长在新行，原导入行永远素着）；
- 素行无 `next_review_date` → 按到期判定**永久到期**——旧写回只按 id 更新保留行，素行冻住 → 该词天天出现在到期卡组；
- 现行导入链（按词查重 v103 + 按钮防重入）不会再造新重复行；v115③ 的同词全行推进会自然清账；物理删行可选（cleanup_vocab_dupes.sql 先例）。

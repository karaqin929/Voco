## 🔑 核心机制 1：两级对齐的盒子数学（v110）

**两级问题，两批修复**（v108 → v110）：

1. **格子级**（v108）：容器 `pl-1`（防 scale-110 光圈裁切）+ `-ml-1`（负外边距补偿）→ 首格左缘 = 图标左缘；
2. **内容级**（v110）：格子对齐后，熊图仍在格内居中 → 熊脸左缘 = 图标左缘 + (格宽−图宽)/2 ≈ +12px。首格改 `items-start`/`text-left` 后，熊脸左缘 = 格子左缘 = 图标左缘，严格同线。

**附加核验**：bear PNG 192×192 全画布不透明（RGBA alpha bbox = 全图）——熊脸即图缘，无图内透明边距，CSS 对齐即视觉对齐，无需再猜像素补偿。

## 🔑 核心机制 2：内容完整 > 排版克制（v111，产品铁律新立）

**用户指令原文**：「宁可卡片在垂直方向上变长，也绝对不能吃掉用户哪怕一个标点符号。」

**四刀清零 + 一处核实**：
1. 洞察行：v109 的 line-clamp:3 是多行截断的**最后一道闸**——废除后 `<span class="flex-1 min-w-0 break-words">` 纯块级折行；
2. 例证区：`origLine`/`targetLine`（原句/修改/地道/金句四标签共用）`truncate` → `break-words leading-relaxed`，词汇行「3 词 · 连接」同步去 truncate；
3. 话题卡词条行：芯片行原来是 `overflow-hidden whitespace-nowrap`（超宽芯片被静默裁掉，比省略号更隐蔽）→ `flex-wrap` 换行展示；
4. `.badge-source`（语法卡来源徽章）：原生 `text-overflow:ellipsis` → `white-space:normal + overflow-wrap:break-word`；
5. 容器：`card()` 白卡 / `bodyBox()` 灰底盒本就 height:auto 零固定高度——实测核实无需改。

**收口复核**：全前端 grep `truncate|line-clamp|ellipsis|text-overflow` 仅剩注释提及，实际样式零残留。此规则已写入 CLAUDE.md 铁律区，**覆盖 v105 单行截断 / v109 例证区保持截断两条历史指令**。

## 🔑 核心机制 3：熊条三级对齐的教训（v108 → v110 → v112）

**「对齐」与「间距均匀」是一对约束，局部修复必然顾此失彼**：

- v108 对齐格子左缘 → 熊图仍居中，熊脸缩进 ~12px（用户不满）；
- v110 首格左对齐 → 熊脸对齐了，但 1→2 间距 41px vs 其余 25px（用户不满「惨不忍睹」）；
- v112 全格左对齐 → 熊 i 左缘 = 图标线 + i×(14.28%+4px)，间距恒等 ≈29px，一屏正好 7 只，两个约束同时满足。

**教训**：水平滚动条的内容对齐方式必须是**全格一致的单一规则**（全居中 或 全左对齐），混合对齐必然产生首尾异常间距。

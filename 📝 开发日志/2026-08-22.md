## 🔑 核心机制 1：两级对齐的盒子数学（v110）

**两级问题，两批修复**（v108 → v110）：

1. **格子级**（v108）：容器 `pl-1`（防 scale-110 光圈裁切）+ `-ml-1`（负外边距补偿）→ 首格左缘 = 图标左缘；
2. **内容级**（v110）：格子对齐后，熊图仍在格内居中 → 熊脸左缘 = 图标左缘 + (格宽−图宽)/2 ≈ +12px。首格改 `items-start`/`text-left` 后，熊脸左缘 = 格子左缘 = 图标左缘，严格同线。

**附加核验**：bear PNG 192×192 全画布不透明（RGBA alpha bbox = 全图）——熊脸即图缘，无图内透明边距，CSS 对齐即视觉对齐，无需再猜像素补偿。

## 🔑 核心机制 2：内容完整 > 排版克制（v111，产品铁律新立）

**用户指令原文**：「宁可卡片在垂直方向上变长，也绝对不能吃掉用户哪怕一个标点符号。」

**四刀清零 + 一处核实**：
1. 洞察行：v109 的 line-clamp:3 是多行截断的**最后一道闸**——废除后 `<span class="flex-1 min-w-0 break-words">` 纯块级折行；
2. 例证区：`origLine`/`targetLine`（原句/修改/地道/金句四标签共用）`truncate` → `break-words leading-relaxed`，词汇行「3 词 · 连接」同步去 truncate；
3. 话题卡词条行：芯片行原来是 `overflow-hidden whitespace-nowrap`（超宽芯片被静默裁掉，比省略号更隐蔽）→ `flex-wrap` 换行展示；
4. `.badge-source`（语法卡来源徽章）：原生 `text-overflow:ellipsis` → `white-space:normal + overflow-wrap:break-word`；
5. 容器：`card()` 白卡 / `bodyBox()` 灰底盒本就 height:auto 零固定高度——实测核实无需改。

**收口复核**：全前端 grep `truncate|line-clamp|ellipsis|text-overflow` 仅剩注释提及，实际样式零残留。此规则已写入 CLAUDE.md 铁律区，**覆盖 v105 单行截断 / v109 例证区保持截断两条历史指令**。

## 🔑 核心机制 3：熊条四级对齐的教训（v108 → v110 → v112 → v113）

**「对齐」「间距均匀」「恰好 N 只」三个约束互相咬合，局部修复必然顾此失彼**：

- v108 对齐格子左缘 → 熊图仍居中，熊脸缩进 ~12px（用户不满）；
- v110 首格左对齐 → 熊脸对齐了，但 1→2 间距 41px vs 其余 25px（用户不满「惨不忍睹」）；
- v112 全格左对齐 → 间距恒等、左端齐平，但最后一格残留 (格宽−熊宽)≈28px 右空档 → 右锚定时最新熊距「去打卡」右缘 28px、一屏只有 6 只多（用户不满）；
- v113 列模板方程求解 → `repeat(n-1, calc((100% - 24px)/6 - 4px)) 28px`，间距 p=(P−24)/6 使 6p+24=P **恒成立**：任意屏幕恰好 7 只、左右两端同时齐平（左视图首熊=图标线、右视图最新熊=去打卡右缘）、间距严格恒等。

**教训**：水平滚动条需要「两端齐平 + 恰好 N 只」时，% 网格 + 对齐类只能满足部分组合，**必须列模板方程求解**（6p+24=P，p=间距），且两端 padding/margin 必须严格镜像（pl-1/-ml-1 ↔ pr-1/-mr-1），否则右锚定时选中熊的光圈会被 overflow 裁掉。

## 🔑 核心机制 4：SRS 翻卡正面认知重构的六轮收敛（v114）

**用户逐轮否决记录**（每轮都是真金白银的认知论教训）：

1. **元描述 ✗**（"这次怎么说更地道？"）——教练式废话，不产出具象线索；
2. **句型框架 ✗**（"挖空 agree 是什么用意？这不是训练目的"）——**地道句的「地道核心」正是功能词构式+搭配（couldn't … more / been meaning to），框架把它整块给出 = 提前给答案，检索强度归零**。此后「首字母骨架」连功能词都不给全文；
3. **词数指令 ✗**（"说出 15 词的地道整句"）——"我不可能数字数"，旁观者度量，回忆时的大脑不按词数检索；
4. **纯锚点 ✗**——只有错误原句不足以触发升级方向；
5. **设备指令** ✓——每卡不同的升级手段名（同位语结构/宾语从句句型/地道习语/更精准的词汇…，31 词词典从解析抽取 + 目标句形状兜底）；
6. **+习语片段（括号）+意图（冒号）定案** ✓——`尝试用「地道习语」（a must-see）：推荐电影，升级原句表达`。

**抽取管线与防泄底三闸**：deviceMatch（词序敏感首命中）→ deviceContext（A 设备前最后「用」→ 功能段 / B 句首设备 → 其后首句 / C 设备前最后一段 ≥2 字；解析兜底要求「用」后紧跟英文，防惯用法/用于构词用误命中）→ deviceFragment（explanation 英文 run 与目标句连续重合 + 原句序列排除 + 相邻合并「 … 」+ **覆盖 >60% 目标句词数即隐藏**，防 fascinating 这类"习语≈整句"卡无物可练）→ isAnalysisExpl 把解析类 explanation 锁死翻面 🎬（术语正则/超长/bigram 三判定，宁藏勿泄）。范围锁定：仅每日打卡 15 句句型复习翻卡，对比阅读卡片零改动（hunk 级 git diff 验证）。

## 🔑 核心机制 5：嵌套滚动的结构性根因（v114）

**双重滚动条 = 两个条件叠加**：定高容器（#speak-player height:calc(100dvh−92px) + overflow-y:auto）+ 内部超长（.srs-flip-back `position:absolute; inset:0` 钉死在正面面积里 = 隐形固定高度，解析超长只能卡片内滚）。**3D 翻卡背面的绝对定位钉死是卡片内滚的根因**。

**修复 = 全交给 Body**：① #speak-player height→min-height、overflow-y:auto→visible；② 翻卡改 **Grid 单格堆叠**（display:grid + 两面对齐 grid-area:1/1）——行高 = max(正,背)，背面 overflow:visible !important + height:auto !important（auto 是 grid item 默认值，align-self:stretch 依然生效 → 两面同高盖满卡片，无背景缺口）；③ 三处空态 h-full 居中改内联 min-height（同值迁移零视觉差）。全库 grep 证实零 JS 依赖 speak-player 滚动位置，列表页无 overflow:hidden 祖先零回归。
